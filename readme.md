# Resting State Paradigm

A PsychoPy-based resting state paradigm for M/EEG recordings. The task collects brain activity across three phases: artifact recordings, eyes-open resting state, and eyes-closed resting state. Instructions are presented in German.

## Task Overview

### 1. Artifact Recordings (optional)

Participants perform five common M/EEG artifact movements so that these signals can later be identified and removed from the resting state data:

| # | Artifact         | Instruction (German)                                   |
|---|------------------|--------------------------------------------------------|
| 1 | Eye rolling      | Augen rollen                                           |
| 2 | Eye blinking     | Blinzeln                                               |
| 3 | Eye saccades     | Augen hin und her bewegen                              |
| 4 | Teeth grinding   | Kiefer anspannen und mit den Zähnen knirschen          |
| 5 | Swallowing       | Mehrfach hintereinander schlucken                      |

Each artifact is preceded by a 3-second countdown. This phase can be toggled on/off in the participant dialog.

### 2. Eyes-Open Resting State (5 min)

Participants fixate a central cross on the screen for 5 minutes while sitting quietly and relaxed.

### 3. Eyes-Closed Resting State (5 min, optional)

Participants close their eyes when they hear a **high-pitched tone (660 Hz, 1 s)** at the start of the recording and open them again when they hear a **low-pitched tone (220 Hz, 1 s)** at the end. This phase can be toggled on/off in the participant dialog.

## Versions

Two versions of the task are provided for compatibility with different PsychoPy installations:

| File                       | PsychoPy Version | Python   | Audio Library  | Window Size |
|----------------------------|------------------|----------|----------------|-------------|
| `resting_task_v2026.psyexp` | 2026.1.1         | >= 3.10  | ptb (PsychToolbox) | 1024 x 768  |
| `resting_task_v2021.psyexp` | 2021.2.3         | >= 3.8   | pyo            | 1920 x 1080 |

Each `.psyexp` file has a corresponding `.py` script that was auto-generated by the PsychoPy Builder. **These generated `.py` files must never be hand-edited** — any change is lost on the next Builder compile. Fixes go through either a Code Component in Builder (regenerates into the `.py`) or a hand-written helper module in `funcs/` that the generated scripts import.

Both versions target the OPM lab's acquisition computer (Windows, PsychoPy 2024.2.4 installed) together with a VPixx PROPixx projector, a RESPONSEPixx button box, and a VPixx SoundPixx audio device. See **Hardware Integration** below.

## Requirements

- [PsychoPy](https://www.psychopy.org/) (v2026.1.1 recommended, v2021.2.3 for legacy; lab acquisition computer runs 2024.2.4)
- Python >= 3.10 (or >= 3.8 for the legacy version)
- `pypixxlib` for the VPixx hardware (button box, trigger patch readout on the OPM side, and SoundPixx audio)

## Hardware Integration

All three subsystems below are implemented in `funcs/` and shared by both experiment versions, so a fix only has to be made once. Each degrades gracefully (falls back to keyboard/silence with a printed warning) if the hardware isn't connected, so the task can still be run/tested off-site.

### Button box (`funcs/response.py`)

Read via the RESPONSEPixx handheld's digital inputs (`DPxGetDinValue`). The idle DIN value is captured once at startup; a bit counts as "pressed" when it differs from that idle baseline, so the wiring polarity doesn't need to be known in advance. Falls back to the keyboard (arrow keys) if the DATAPixx isn't ready. Run `button_test.py` standalone to check the box is detected and see which bit each button flips.

### Trigger patch (`funcs/trigger.py`)

The OPM system reads triggers via VPixx Pixel Mode B: the blue channel of a small patch drawn at the screen's top-left corner (pixel (0,0)) is decoded in hardware into DOut 16-23. `TRIGGER_VALUES` in `funcs/trigger.py` is the single source of truth for every trigger value sent during the task:

| Event                    | Key             | Value |
|---------------------------|-----------------|-------|
| Eyes-open recording start | `eyes_open`     | 10    |
| Eyes-closed recording start | `eyes_closed`  | 20    |
| Artifact: eye rolling      | `eyes_roll`     | 30    |
| Artifact: eye blinking     | `eyes_blink`    | 32    |
| Artifact: eye saccades     | `eyes_saccade`  | 34    |
| Artifact: teeth grinding   | `clench_jaw`    | 36    |
| Artifact: swallowing       | `swallow`       | 38    |

The artifact values are looked up by the `trigger_key` column in `instructions/artifact_instruction.csv`, so adding a new artifact just means adding a matching key to both the CSV and `TRIGGER_VALUES`. Adjust the pulse timing (default: onset at 0.0 s, offset at 0.5 s into the routine) via the `t_onset`/`t_offset` arguments passed to `TriggerPatch.update()` in Builder.

### VPixx SoundPixx audio (`funcs/audio.py`)

The eyes-closed phase's start/stop tones are played through the VPixx SoundPixx device (onboard DATAPixx RAM buffer + audio schedule), not the PC's normal sound card, since the earphones in the shielded room are wired to the DATAPixx. Frequency, duration, and volume are set where `VPixxTones` is constructed in each script's Begin Experiment Code Component (currently 660 Hz start / 220 Hz stop / 1.0 s / volume 0.2). Run `audio_test.py` standalone to confirm both tones are audible through the earphones before running the full task.

## How to Run

1. Install PsychoPy (standalone installer or via pip).
2. Open the appropriate `.psyexp` file in PsychoPy Builder:
   - `resting_task_v2026.psyexp` for PsychoPy >= 2026.1.1
   - `resting_task_v2021.psyexp` for PsychoPy 2021.2.3
3. Adjust the presentation modalities (screen size or full screen etc.) according to your setup. Also adjust the trigger values according to your setup (see **Hardware Integration** below).
4. Click the **Run** button in the Builder, or run the corresponding `.py` script directly.
5. Fill in the participant dialog:

   | Field                  | Description                                | Default    |
   |------------------------|--------------------------------------------|------------|
   | participant            | Participant ID                             |            |
   | gender                 | Participant gender                         | `f`        |
   | date_of_birth          | Date of birth (DD.MM.YYYY)                 |            |
   | ethnicity              | Participant ethnicity                      |            |
   | diagnosis              | Clinical group label                       | `control`  |
   | artifact_recording     | Run artifact phase (1 = yes, 0 = no)       | `1`        |
   | eyesclosed_recording   | Run eyes-closed phase (1 = yes, 0 = no)    | `1`        |

6. Data files are saved to the `data/` folder with the naming convention:
   ```
   data/<participant>_resting_task_<version>_<phases>_<date>
   ```
   where `<phases>` encodes which phases were run:
   - `eyeop_eyecl`: recording also contains an eyes closed part
   - `eyeop_artfrec`: recording also contains an artifact recording
   - `eyeop_eyecl_artfrec`: reording contains all parts

## Instruction Text Formatting

Colored text chunks in the instruction CSVs (e.g. to highlight a keyword) are written with a single canonical tag: `<c=COLOR>text</c>`, where `COLOR` is anything PsychoPy accepts (a name like `black`/`red`/`blue`, or a hex code like `#ff0000`). This one format is used in the CSV regardless of which experiment version reads it — each version's own text component understands something different, so the conversion happens in code, not in the data:

- **v2021** uses `visual.TextStim`, which can't render inline color at all. Its Begin Routine code already strips any `<...>` tag before display, so `<c=...>` just disappears cleanly and instructions show as plain text.
- **v2026** uses `visual.TextBox2`, which has its own `[color=COLOR]text[/color]` tag. `funcs/markup.py`'s `to_textbox2()` rewrites `<c=...>` into that before each textbox's `setText()` call.

Never write `[color=...]` directly into the CSVs — that's the v2026-only intermediate format produced by `to_textbox2()`, not the source format.

## Customization

- **Instructions**: Edit the CSV files in `instructions/` to change instruction text or add slides — see **Instruction Text Formatting** above for coloring text. The task loads these dynamically so no code changes are needed.
- **Recording duration**: Modify the duration of the eyes-open and eyes-closed routines in the PsychoPy Builder (default: 300 s each).
- **Trigger values**: Edit `TRIGGER_VALUES` in `funcs/trigger.py` — see **Hardware Integration** above.
- **Tone parameters**: The start/stop tones for the eyes-closed phase are played twice in parallel and must be kept in sync manually: once by the native PsychoPy Sound components (Builder, frequency/duration/volume) and once by `VPixxTones` over SoundPixx (the arguments passed to `VPixxTones(...)` in each script's Begin Experiment Code Component).
- **Window size**: Set in the Experiment Settings dialog within the Builder.
